# 文章知识库支持率评审 Skill

`deepeval-article-audit` 用来检查一篇已经写完的英文文章中，有多少事实性内容能够在指定知识库文件中找到依据。

它参考 DeepEval Faithfulness 的核心步骤和计算公式，但由当前 Codex 完成事实拆分和证据判断，不调用付费评审 API。

所有结果统一标注：

> DeepEval Faithfulness 规则复现（Codex 评审，非 DeepEval 官方运行）

## 一句话理解

把文章中的事实逐条拆开，再检查每条事实是否有知识库原文支持。

```text
Faithfulness = 知识库支持的事实主张数 ÷ 文章全部事实主张数
```

它测量的是“文章事实有没有知识库依据”，不是“文章复制了多少知识库原话”。改写、同义替换和语序变化不会自动被判为不支持。

## 适合什么情况

- 检查Codex或其他AI写出的文章是否真正使用了企业知识库；
- 查找文章中没有知识库依据的事实；
- 查看文章事实与知识库原文的对应位置；
- 批量比较多篇文章的知识库支持率；
- 生成可以交给内容运营复查的明细表和网页。

当前版本主要用于英文文章和Markdown格式的写作输入/知识库文件。

## 不适合替代什么

本Skill不等同于：

- RAGSEO逐字引用率；
- 连续词组覆盖率；
- 原文重复率或查重率；
- 文章整体质量、SEO质量或合规审核；
- DeepEval官方程序加固定评审模型的运行结果。

这些指标回答的问题不同，不能混在一起平均。

## 需要提供什么

最少提供两类文件：

1. **文章文件**：已经完成的文章正文；
2. **知识文件**：文章写作时允许使用的知识库资料或文章写作输入。

可以一次提供一篇或多篇文章。每篇文章必须能够与自己的知识文件明确配对。

如果文件夹中存在多个可能的文章或知识文件，且无法确定对应关系，Skill会先询问，不会自行混用。

## 小白使用方法

在Codex中直接说：

```text
使用 $deepeval-article-audit。
文章文件是：D:\项目\40_最终文章与引用率.md
知识库文件是：D:\项目\30_文章写作输入.md
结果输出到：D:\项目\评审结果
```

批量评审时可以说：

```text
使用 $deepeval-article-audit，评审这个文件夹中的全部已完成文章。
每篇文章的“30_文章写作输入.md”是知识文件，
“40_最终文章与引用率.md”是文章文件，
结果输出到指定的新文件夹，不要覆盖原文件。
```

不需要提供API Key，也不需要购买额外的评审模型调用额度。运行会消耗当前Codex的正常使用额度。

## 会输出什么

### 1. 每篇文章的明细表

文件名：

```text
<文章编号>_faithfulness_details.md
```

每一行对应一个事实主张，包含：

- 主张编号；
- 文章原始行号；
- 文章原文；
- 拆分后的事实主张；
- 支持或不支持；
- 对应知识库原文；
- 知识文件及行号；
- 判断理由。

### 2. 整体统计表

文件名：

```text
faithfulness_summary.md
```

一篇文章一行，显示：

- 支持主张数（分子）；
- 全部事实主张数（分母）；
- 不支持主张数；
- Faithfulness百分比；
- 评审模式。

### 3. 交互式网页

文件名：

```text
faithfulness_highlight.html
```

网页把文章原文、事实主张、判断理由和知识库证据放在同一个展开卡片中。可以切换文章，也可以只查看“支持”或“不支持”的主张。

证据不会放在一个与文章脱离的固定右上角窗口中。

### 4. 审计过程文件

```text
<文章编号>-prepared.json
<文章编号>-judgments.json
```

这两个文件记录正文拆分、候选证据和最终判断，便于以后追查分子、分母和证据位置。

## 计算口径

### 什么进入分母

分母是文章正文中全部可以独立判断真假的事实主张。

例如：

```text
Model A uses a xenon lamp and covers 190–900 nm.
```

会拆成：

1. Model A uses a xenon lamp.
2. Model A covers 190–900 nm.

因此分母增加2，而不是增加1。

### 什么不进入分母

- 文章标题和各级小标题；
- 网址、目录和文件元数据；
- 纯问题和修辞句；
- 不包含事实理由的纯建议或操作指令；
- 文章后的审核记录、引用率记录等管理内容。

### 怎样算支持

满足以下任一情况，可以判为支持：

- 知识库原文直接陈述相同事实；
- 文章进行了改写，但没有增加实质信息；
- 该事实可以由知识库原文合理、直接地推出。

每个支持主张必须附带知识库中的连续原文、文件路径和真实行号。

### 怎样算不支持

- 知识库完全没有提到；
- 知识库只支持主张的一部分；
- 文章扩大了适用范围或补充了新结论；
- 文章与知识库矛盾；
- 说法符合常识，但提供的知识库没有依据。

本Skill不使用部分分。遇到一句话一部分支持、一部分不支持时，继续拆开判断。

## 为什么同一篇文章可能与旧结果不同

DeepEval的公式是固定的，但“文章被拆成多少条事实主张”需要评审模型判断，不存在天然固定的分母。

本Skill为了让结果更容易复查，固定使用**原子事实主张口径**。旧测试如果把一整句产品参数算作一条，而本Skill把光学结构、带宽、检测器和软件分别计算，分母就会增加。

因此：

- 只有使用同一版本Skill、同一知识文件和同一拆分口径的结果，才适合直接比较；
- 不要把旧版粗粒度结果和新版原子主张结果当作同口径趋势；
- 升级Skill规则后，应保留版本和重新建立基线。

## 如何理解分数

例如：

```text
支持主张数：38
全部事实主张数：56
Faithfulness：38 ÷ 56 = 67.86%
```

这表示文章56条事实主张中，有38条能由指定知识库支持。

它不表示文章有67.86%的文字来自知识库，也不表示剩余32.14%的文字都是错误内容。那些主张可能符合常识，只是没有被本次提供的知识库证明。

## 结果复查建议

内容运营优先检查：

1. 不支持主张是否确实没有知识库依据；
2. 复合句是否拆得过细或过粗；
3. 知识库证据是否与文章主张真正对应；
4. 产品参数、公司事实、法规要求和数据是否有明确来源；
5. 是否漏交了文章实际使用过的知识文件。

如果发现知识文件漏交，应补齐文件后重新运行，而不是人工把该主张直接改成支持。

## Skill目录

```text
deepeval-article-audit/
├── README.md
├── SKILL.md
├── agents/
│   └── openai.yaml
├── references/
│   └── method.md
└── scripts/
    ├── prepare_article_audit.py
    └── render_article_audit.py
```

- `SKILL.md`：Codex执行流程和强制规则；
- `references/method.md`：详细评审口径和判断JSON格式；
- `prepare_article_audit.py`：提取文章正文、知识块和候选证据；
- `render_article_audit.py`：校验证据并生成明细、汇总和网页。

## 当前限制

- 不连接DeepEval官方评审模型，因此不能声称是官方DeepEval结果；
- 主张提取和语义判断仍由当前Codex模型完成，极少数边界主张可能需要人工复核；
- 知识库缺失会直接导致支持率下降；
- 不同Skill版本、不同知识文件或不同拆分规则下的结果不能直接比较；
- 当前预处理和展示主要针对英文正文及Markdown文件设计。
